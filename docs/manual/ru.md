# UncertaintyCalc — руководство пользователя

Это руководство объясняет порядок расчёта неопределённости измерений на платформе UncertaintyCalc. Числа в примерах каждого режима взяты только из проверенных (`verified`) тестовых примеров; для каждого примера указаны документ-источник и идентификатор теста (`id` в `tests/cases/`). Названия кнопок и вкладок в руководстве соответствуют русскому тексту интерфейса.

Руководство написано по состоянию версии расчётного ядра 2.10.0. Текущая версия указывается внизу каждого отчёта.

## 1. Введение

### 1.1. Что делает платформа

UncertaintyCalc — программа, работающая в браузере. Она вычисляет результат измерения `y`, суммарную стандартную неопределённость `u_c`, эффективное число степеней свободы `ν_eff`, коэффициент охвата `k` и расширенную неопределённость `U`, составляет бюджет неопределённости и готовит печатный отчёт. Интерфейс на трёх языках: узбекском, русском, английском.

В рабочем окне семь вкладок: **Ввод данных**, **Тип B** и **Результаты** (режим GUM, Монте-Карло, векторные модели), **Регрессия**, **Top-down**, **Специальные режимы** и **Лаборатория**.

### 1.2. Нормативная основа

| Документ | Для чего используется на платформе |
|---|---|
| JCGM 100:2008 (GUM) | оценивание по типу A и типу B, закон распространения, ν_eff, k |
| JCGM 101:2008 | метод Монте-Карло |
| JCGM 102:2011 | несколько выходных величин, область охвата, неявная модель |
| JCGM 106:2012 | оценка соответствия, правило принятия решения |
| EA-4/02 M:2022 | неопределённость при калибровке, k = 2 |
| ILAC P14:09/2020 | округление U, CMC |
| ILAC G8:09/2019 | правила принятия решения и заключение о соответствии |

Текста ISO/IEC 17025:2017 в репозитории нет (платный стандарт). Ссылки на него в программе (например, перечень реквизитов отчёта) не сверены с текстом стандарта и считаются **непроверенными**.

### 1.3. Требования к браузеру

Нужен браузер с поддержкой ES-модулей (версии после 2018 года). В старом браузере выводится только предупреждение. Состояние проверки по браузерам — в [известных ограничениях](../validation/KNOWN_LIMITATIONS.md).

### 1.4. Где хранятся данные

- Текущий расчёт, язык и настройки интерфейса — в хранилище браузера `localStorage`.
- Шаблоны, реестр эталонов, таблица CMC, карты КК, наборы проверки квалификации и валидации, журнал аудита — в хранилище браузера IndexedDB.
- Реквизиты лаборатории (наименование, адрес, номер аккредитации, логотип) — в `localStorage`. Сведения о заказчике и утверждающем лице — только в текущей сессии (`sessionStorage`), при закрытии окна они удаляются.
- Firebase используется только для регистрации, организаций и оплаты. Расчёты, наблюдения, реестр и отчёты на сервер не отправляются.

Отсюда следует: при очистке данных браузера или переходе на другой компьютер расчёты теряются. Важный расчёт сохраняйте в файл кнопкой **Экспорт JSON** (раздел 11), а хранилище экспортируйте через **Данные: экспорт / импорт / аудит**.

## 2. Быстрый старт

1. **Выберите язык.** В верхней части главной страницы есть кнопки **UZ / RU / EN**. Выбор сохраняется в браузере.
2. **Откройте калькулятор.** Нажмите **Открыть калькулятор**. Без регистрации можно выполнить 7 бесплатных расчётов; остаток показан на странице настройки. После этого требуется **Регистрация** или **Вход**.
3. **Настройте расчёт.** На странице **Настройка расчёта** введите **Число измерений (n)** и **Число параметров (p)**. Чтобы начать с готового образца, выберите его в списке **Загрузить пресет** или откройте **Каталог шаблонов**. Затем **Начать расчёт →**.
4. **Введите наблюдения.** На вкладке **Ввод данных** внесите значения измерений в таблицу. Можно вставить из Excel (Ctrl+V) или использовать **Импорт из файла (.xlsx, .csv)**. Входные величины добавляются кнопкой **Добавить параметр** на левой панели.
5. **Запишите формулу модели.** В блоке **Модель измерения** в поле **Формула y = f(x₁…xₙ)** введите, например, `ρ = m / V` и укажите **Единица результата**. При прямом измерении с одним параметром формулу можно оставить пустой (y = x).
6. **Рассчитайте тип A.** **Рассчитать неопред. типа A →**.
7. **Введите источники типа B.** На вкладке **Тип B** кнопкой **Добавить компонент** (или **Выбрать из реестра**) добавьте каждый источник: параметр, распределение, полуширину или U и k из сертификата. На этой же вкладке находятся настройки расчёта: **Вероятность охвата P**, **Коэффициент охвата k**, **Тип модели**, **Пределы допускаемой погрешности MPE (±)**, CMC, **Правило принятия решения**.
8. **Получите результат.** **Рассчитать суммарную неопред. →**. На вкладке **Результаты** выводятся бюджет неопределённости, результат и **Результаты проверки** (замечания линтера).
9. **Отчёт.** Выберите **Форма отчёта**, заполните **Реквизиты** и нажмите **Печать отчёта**.

Чтобы начать новый расчёт — **Новая сессия**.

### 2.1. Шаблоны

В окне **Каталог шаблонов** находятся шаблоны методик. Кнопка **Рассчитать** на карточке загружает шаблон в расчёт, **Редактор** открывает шаблон для правки, **Новый шаблон** и **Импорт шаблона (JSON)** добавляют собственный шаблон.

Статус шаблона: `DRAFT` → `REVIEWED` → `APPROVED`. Все шаблоны, поставляемые с программой, сейчас имеют статус `DRAFT` и не содержат числовых значений (полуширина, U, k) — эти значения лаборатория вносит из своих сертификатов и методики. Порядок составления шаблона — в [руководстве по шаблонам](../TEMPLATE_GUIDE.md).

В окне **Настройки лаборатории** задаются значения по умолчанию для лаборатории (P, метод k, правило ν_eff, округление, правило принятия решения по умолчанию, настройки Монте-Карло и другие). Порядок приоритета: значение программы, затем лаборатории, затем шаблона, затем значение, введённое пользователем на странице расчёта.

## 3. Режим GUM (закон распространения неопределённости)

### 3.1. Оценивание по типу A

Для каждой входной величины по ряду наблюдений вычисляются среднее, стандартное отклонение `s` и стандартная неопределённость среднего `u_A = s / √n`, число степеней свободы `ν = n − 1` (JCGM 100:2008 §4.2). Под таблицей показаны среднее, дисперсия, `s` и `u_A`.

Если наблюдение одно или повторяемость известна заранее (объединённое стандартное отклонение `s_p`), введите её как источник типа B — так сделано в примере ниже.

### 3.2. Распределения типа B

| Название в интерфейсе | Стандартная неопределённость |
|---|---|
| Прямоугольное (равномерное) | a / √3 |
| Нормальное (Гауссово) | U / k |
| Треугольное | a / √6 |
| U-образное (арксинусное) | a / √2 |
| Дискретность / цена деления d | d / (2√3) |
| Трапецеидальное | a·√((1 + β²) / 6) |
| Криволинейная трапеция — неточные границы | √(a² / 3 + d² / 9) |
| Экспоненциальное — неотрицательная величина | u = x |
| Логнормальное | U / k |

Первые пять — по JCGM 100:2008 §4.3 и JCGM 101:2008 §6.4; трапецеидальное, криволинейная трапеция и экспоненциальное — JCGM 101:2008 §6.4. Логнормальное распределение не подтверждено примером из источника (**unverified**).

В поле полуширины можно ввести число или выражение (например, `25 / sqrt(3)`). Поле **Множитель** переводит источник в единицы параметра; коэффициент чувствительности модели ∂y/∂x вычисляется автоматически.

**Важное правило.** Пределы допускаемой погрешности (MPE) калибруемого прибора никогда не становятся источником неопределённости автоматически. MPE вводится только для оценки соответствия (раздел 10). MPE / допуск из реестра эталонов также не предлагается как источник.

### 3.3. Корреляция

- Если отмечено **Измерения парные**, коэффициент корреляции вычисляется по наблюдениям (тип A).
- **Ковариация типа B u_B(xᵢ,xⱼ)** вводится, только если обе величины зависят от общего эталона, прибора или поправки (JCGM 100:2008 §5.2.4, F.1.2.3). Иначе оставьте 0.

В результатах влияние корреляции на u_c показано отдельно.

### 3.4. ν_eff и коэффициент охвата k

`ν_eff` вычисляется по формуле Уэлча–Саттертуэйта (JCGM 100:2008 G.4.1). Настройка **Коэффициент охвата k**:

- **По Стьюденту, из ν_eff** — k = t_P(ν_eff);
- **k = 2 (фиксированный)** — по EA-4/02 M:2022.

При дробном ν_eff правило по умолчанию — **Округление вниз (⌊ν⌋)**: k = t_P(⌊ν_eff⌋) (JCGM 100:2008 G.4.1, примечание 1). **Интерполяция** — необязательная настройка лаборатории. Применённое правило указывается в отчёте.

### 3.5. Округление

Промежуточные вычисления не округляются. Округление выполняется только в отчёте:

- U — не более 2 значащих цифр (ILAC P14:09/2020 §5). После округления вверх также остаются 2 цифры: 0,0999 → 0,10.
- y — до последнего разряда U, по правилу «половина — от нуля» (совпадает с Excel ROUND): −0,125 → −0,13.

В файлах экспорта числа приводятся неокруглёнными, округлённый вид даётся отдельной строкой.

### 3.6. Тип модели и MPE

Настройка **Тип модели** указывает, чем является результат модели: **погрешность показаний E = X − X_ref**, **значение величины Y (с номиналом)** (при этом вводится и **Номинальное значение**) или **не указан**.

Программа не считает результат «погрешностью» по своему усмотрению. Если тип модели не указан, заключение о соответствии не выдаётся. В старых сохранённых расчётах тип модели — «не указан».

### 3.7. Результаты проверки (линтер) и принятие с обоснованием

После каждого расчёта программа проверяет результат по правилам и показывает замечания в блоке **Результаты проверки**. Уровней три: **Ошибка**, **Предупреждение**, **Сведения**. У каждого замечания есть пояснения «Почему» и «Как исправить», а также пункт источника. Перечень правил — в [правилах линтера](../LINTER_RULES.md).

Если ошибку или предупреждение нельзя устранить, замечание можно **Принять с обоснованием**: в поле **Обоснование** вводится комментарий не короче 10 символов и нажимается **Подтвердить**. Комментарий записывается в журнал аудита (с ролью и временем) и выводится в отчёте.

- Если есть непринятое замечание уровня «ошибка», отчёт выводится с водяным знаком **НЕОФИЦИАЛЬНО**.
- Все замечания видны в печатном отчёте; настройки, скрывающей их, нет.
- Результат с U = 0 или U < CMC не попадает в отчёт без предупреждения. Настройка лаборатории: **Явно отметить в отчёте** (по умолчанию) или **Блокировать отчёт**.

### 3.8. Пример: калибровка гири 10 кг

Источник: EA-4/02 M:2022, Supplement 1, S2.2–S2.11 (таблица бюджета S2.9), с. 29–30. Тестовый пример: `ea4-02-s2` (verified).

Модель: `mX = mS + mD + dm + mC + B`, единица результата мг. Настройки: P = 0,9545, **k = 2 (фиксированный)**.

Входные значения: mS = 10 000 005 мг, dm = 20 мг, остальные 0.

| Источник | Параметр | Распределение | Значение |
|---|---|---|---|
| m_S: сертификат U = 45 мг, k = 2 (S2.3) | mS | Нормальное | U = 45, k = 2 |
| m_D: ±15 мг (S2.4) | mD | Прямоугольное | a = 15 |
| δm: s_p = 25 мг, n = 3 (S2.8) | dm | Нормальное | `25 / sqrt(3)`, k = 1 |
| δm_C: ±10 мг (S2.5) | mC | Прямоугольное | a = 10 |
| δB: ±10 мг (S2.6) | B | Прямоугольное | a = 10 |

Результат в источнике:

| Величина | Значение в источнике | Пункт источника |
|---|---|---|
| m_X | 10 000,025 г | S2.9 |
| u(m_X) | 29,2 мг | S2.9 |
| k | 2 | S2.10 |
| U | 58 мг | S2.10 |

Примечание: источник вычислил U из округлённого u = 29,2 мг (2 × 29,2 ≈ 58). Программа не округляет промежуточные значения: u_c = 29,26 мг, U = 58,52 мг, в отчёте до 2 значащих цифр — 59 мг. Расхождение вызвано промежуточным округлением в источнике; эта причина записана в допуске теста.

Пример правила для ν_eff: `jcgm100-h1` (JCGM 100:2008, H.1, с. 79–84) — ν_eff = 16,7, при P = 99 % k = t₉₉(16) = 2,92, u_c = 32 нм, U₉₉ = 93 нм. Здесь ν_eff округляется вниз до 16.

## 4. Метод Монте-Карло (JCGM 101:2008)

На вкладке **Результаты** в блоке **Проверка методом Монте-Карло (JCGM 101:2008)** нажимается **Запустить моделирование**. Расчёт выполняется в фоновом потоке, показывается ход выполнения, остановить можно кнопкой **Отменить**.

### 4.1. Настройки

| Настройка | Выбор | Примечание |
|---|---|---|
| Цель расчёта | **Проверка GUM (δ/5)** или **Обычный MCM (δ)** | по умолчанию — проверка GUM |
| Число испытаний M | **Адаптивное M** или **Фиксированное M** | по умолчанию — адаптивное (JCGM 101:2008 §7.9.4); предел M — 10⁷ |
| n_dig | число значащих цифр u(y), считающихся надёжными | по умолчанию 2; из него получается числовой допуск δ (§7.9.2) |
| Вид интервала | **Наименьший интервал** или **Симметричный интервал** | по умолчанию — наименьший |
| **Начальное значение (seed)** | целое число | по умолчанию 20261110 |

Генератор — расширенный Вихмана–Хилла (JCGM 101:2008 C.3.3). Входы типа A берутся из смещённого распределения Стьюдента (§6.4.9), входы типа B — из своего распределения.

### 4.2. Проверка результата GUM

При проверке GUM интервал Монте-Карло сравнивается с интервалом GUM (JCGM 101:2008 §8). При этом числовой допуск Монте-Карло должен составлять δ/5 (§8.2). Результат: **Результат GUM подтверждён** или **Результат GUM не подтверждён**. Если не подтверждён, в отчёте в качестве результата приводится интервал Монте-Карло.

- Если достигнут предел M или фиксированного M недостаточно — выводится замечание «не стабилизировался» и в отчёте записывается «достигнуто 2s». При n_dig = 2 и δ/5 это ожидаемая ситуация для многих расчётов.
- Снижение допуска до δ — только настройка лаборатории; в отчёте это отмечается.
- В режиме **Обычный MCM** δ и вывод по §8 не приводятся.
- Для t-входа с числом степеней свободы ν ≤ 2 значение u(y) не определено — приводится только интервал охвата.
- Если среди коррелированных входов есть распределение, отличное от нормального, результат Монте-Карло не выдаётся (действует результат GUM). Исключение — парные наблюдения типа A.

### 4.3. Воспроизводимость

Одинаковое начальное значение и одинаковые настройки дают одинаковый результат. Начальное значение, название генератора, M и n_dig записываются в отчёте.

В разных движках браузеров сырое (неокруглённое) значение может отличаться в последнем разряде — относительное расхождение не превышает 1·10⁻¹⁴; округлённый результат одинаков. Причина: последовательность случайных чисел везде одна и та же, но функции `log`, `sin`, `cos` в разных движках отличаются в последнем разряде. Побитовая воспроизводимость гарантируется только в пределах одной версии JS-движка. В отчёте указывается браузер, в котором выполнен расчёт. Предел (1·10⁻¹⁴) проверяется автоматически (Chromium, Firefox, WebKit); исключение — отдельные плохо обусловленные производные величины (например, наименьшее собственное значение почти вырожденной ковариационной матрицы): их список и измеренные расхождения приведены в отчёте о валидации. Записываются только краткое название и версия браузера (в файле расчёта и в нижней части печатного отчёта).

Результаты Монте-Карло, сохранённые до версии ядра 2.6.0, в точности воспроизводятся старым генератором; новые расчёты выполняются только генератором Вихмана–Хилла.

### 4.4. Пример: аддитивная модель с четырьмя нормальными входами

Источник: JCGM 101:2008, §9.2.2, Table 2, с. 35–37. Тестовый пример: `jcgm101-9-2-2-mcm-adaptive` (verified).

Модель: `Y = X1 + X2 + X3 + X4`. Каждый вход: оценка 0, нормальное распределение, стандартная неопределённость 1. P = 0,95. Настройки: адаптивное M, n_dig = 2, проверка GUM (δ/5), симметричный интервал.

| Величина | Значение в источнике (Table 2, Adaptive MCM) |
|---|---|
| y | 0,00 |
| u(y) | 2,00 |
| 95 % интервал охвата | [−3,92; 3,92] |
| M | 1,23·10⁶ и 1,02·10⁶ (два применения в источнике) |
| Проверка GUM | подтверждено |

M — случайная величина, поэтому сравнивается только её порядок. Та же модель с фиксированным M = 10⁶ — `jcgm101-9-2-2-mcm`.

## 5. Модели с несколькими выходами и неявные модели (JCGM 102:2011)

### 5.1. Несколько выходных величин

В блоке **Модель измерения** кнопкой **Добавить формулу выходной величины** добавляются вторая и следующие формулы. Результат — вектор: для каждого выхода вычисляются y, u, U, ковариация между выходами и **Корреляционная матрица выходных величин r(y_i, y_j)** (U_y = C_x·U_x·C_xᵀ, JCGM 102:2011 §6.2).

- Значение U каждого выхода — отдельное, по его собственному одномерному правилу.
- Совместный охват даётся только через **Область охвата**: эллипс или эллипсоид (k_p) и прямоугольная область (k_q) — JCGM 102:2011 §6.5. Для двух выходов показывается чертёж эллипса.
- Результат и путь расчёта с одним выходом не изменились.
- Есть и многомерный метод Монте-Карло (JCGM 102:2011 §7). Для двух выходов по результату Монте-Карло показывается также **Наименьшая область охвата (приближение)**.

### 5.2. Неявная модель

Модель вида h(Y, X) = 0 (JCGM 102:2011 §6.3) поддерживается, но пока вводится только через файл расчёта (JSON) или шаблон — формы ввода на основном экране нет. Для каждой неизвестной обязательно начальное значение: программа его не придумывает. Если решение не сходится или система уравнений вырождена, вместо результата выводится замечание об ошибке.

### 5.3. Ограничения

- Для неявной модели метода Монте-Карло нет: программа не линеаризует молча, а сообщает об ошибке.
- Наименьшая область охвата — только для двух выходов.
- При нескольких выходах и нескольких точках калибровки единого k нет; совместный охват — отдельно для каждой точки.
- Порог линтера по корреляции выходов (|r| > 0,5) ожидает подтверждения владельца.

### 5.4. Пример: аддитивная модель с двумя выходами

Источник: JCGM 102:2011, §9.2.2, Table 3, с. 36. Тестовый пример: `jcgm102-9-2-2-guf` (verified).

Модель: `Y1 = X1 + X3`, `Y2 = X2 + X3`. Каждый вход: оценка 0, нормальное распределение, стандартная неопределённость 1. P = 0,95.

## 7. Top-down

Вкладка **Top-down** — мастер из трёх шагов: **Тип данных**, **Ввод данных**, **Бюджет и результат**. Неопределённость оценивается по данным валидации и контроля качества: по Nordtest TR 537 — u(R_w) (внутрилабораторная воспроизводимость) и u(bias); по QUAM:2012 — извлечение R_m и t-тест, неопределённость, зависящая от уровня, эмпирическая (определяемая методом) величина. Источники u(R_w): ряд контрольной пробы, разности дубликатов, границы контрольной карты, готовое s или CV %. Источники смещения: стандартный образец (CRM), раунды проверки квалификации (PT), извлечение (recovery).

Правила:

- Каждая величина задаётся либо в единицах, либо в относительной шкале; смешение относительных и абсолютных значений — ошибка.
- k = 2 (P ≈ 95 %). ν_eff вычисляется и показывается; при ν_eff < 30 выводится предупреждение и предложение t_P(⌊ν_eff⌋), но k автоматически не меняется.
- Если один фактор учтён дважды, выводится предупреждение; оно видно и в печатном отчёте.
- Если для эмпирической величины введено смещение, программа спрашивает, каким методом получено опорное значение.

Части, опирающиеся на ISO 21748 (проверка лабораторного s_r, корректировка s_R), — unverified: стандарта в репозитории нет.

### 8.2. Качественные тесты (AQA:2021) — verified

### 8.3. Микробиология — BETA

BETA, не проверено: текста ISO 19036 в репозитории нет, расчёт не подтверждён примером из источника. В результате всегда выводится предупреждение; шаблон этого режима не может получить статус `APPROVED`. Числа примера не приводятся. Перед использованием результата в официальном отчёте сверьте его со стандартом.

### 8.4. Медицинская лаборатория (ISO/TS 20914:2019)

Расчёт подтверждён решёнными примерами ISO/TS 20914:2019 (текста стандарта в репозитории нет — платный). Для каждого уровня IQC u = √(u_Rw² + u_cal²), при необходимости с u_bias. Для каждого уровня укажите интервал применимости: к измеренному результату применяется неопределённость уровня, в интервал которого попадает значение; если интервал не задан, берётся ближайшее среднее и выводится предупреждение. Доступны объединение по лотам, одинаковым измерительным системам и периодам, неопределённость смещения по сертифицированному стандартному образцу, шкала log₁₀ и сравнение с допустимой неопределённостью. Расчётные величины (анионный интервал, осмоляльность, eGFR) рассчитываются в режиме GUM. Эквивалентность IQC и проб пациентов и решение о разделении данных при смене лота — ответственность лаборатории.

## 9. Лаборатория

На вкладке **Лаборатория** пять разделов: **Эталоны**, **CMC**, **Карты КК**, **Проверка квалификации**, **Валидация**. Все записи хранятся только в этом браузере (IndexedDB); каждое создание, изменение и удаление попадает в журнал аудита с ролью и временем.

Роли: эталоны и таблицу CMC редактирует администратор лаборатории; сотрудник добавляет результаты в карту КК и вводит данные PT / валидации. В локальном (гостевом) режиме ограничение по ролям действует на уровне предупреждения; запись реестра или таблица CMC, введённые гостем, отмечаются в отчёте замечанием уровня «сведения».

### 9.1. Реестр эталонов

В карточке каждого эталона хранятся сертификаты калибровки (**Добавить калибровку**): точки, U, k, срок действия, прослеживаемость. В качестве калибровавшей стороны хранится только название организации. Доступны **Импорт из файла**, **Экспорт JSON**, **Экспорт CSV**.

Кнопка **Выбрать из реестра** на вкладке **Тип B** записывает в расчёт копию сертификата (с идентификатором и версией реестра). Если реестр позже изменится, старый расчёт не изменится. Если U, k, ν или распределение изменены вручную, связь с реестром разрывается.

- Срок проверяется относительно даты измерения (а не сегодняшней даты). Эталон с истёкшим сроком — замечание уровня «ошибка», отчёт становится **НЕОФИЦИАЛЬНО**; за 30 дней до истечения — сведения.
- Источники дрейфа и интерполяции только предлагаются: дрейф пользователь отмечает и подтверждает, число для источника интерполяции вводит пользователь.
- Рекомендация по межкалибровочному интервалу — собственная формула проекта (ILAC G24 формулы не даёт).

### 9.2. CMC

Таблица CMC — строки области аккредитации. Если в расчёте выбраны величина CMC и значение X, программа сравнивает U с CMC(X) (ILAC P14:09/2020 §5.5). При U < CMC выводится замечание; U автоматически не заменяется. Вне области сравнение с CMC не выполняется, выводится отдельное замечание.

### 9.3. Карты КК и правила Вестгарда

Есть два вида карт Шухарта: **Индивидуальные значения (I–MR)** и **Подгруппы (X̄–R)**. Коэффициенты карт проверены по NIST/SEMATECH e-Handbook §6.3.2.1–6.3.2.2. Правила Вестгарда — по Westgard 1981; шлюз 1₂s включён по умолчанию (настройка лаборатории). Если правило R₄s применяется к последовательной паре без признака серии, это отмечается как «приближение проекта». Группировки нескольких контрольных материалов в интерфейсе пока нет.

### 9.4. Проверка квалификации (PT)

В серию PT добавляются раунды (**Добавить раунд** или **Импорт из файла**): результат x, приписанное значение x_pt, σ_pt, неопределённости. Программа вычисляет показатели z, z′, ζ и E_n. Показатель, который нельзя вычислить, остаётся пустым с указанием причины; показатель не заменяется другим автоматически. Раунды PT можно передать в мастер top-down как источник смещения.

Формулы показателей и границы оценки (|z| ≤ 2, |z| ≥ 3, |E_n| ≤ 1) опираются на ISO 13528 — стандарта в репозитории нет, поэтому они **unverified**; в результате об этом всегда выводятся сведения. Проверенного примера из источника для PT пока нет, поэтому числовой пример здесь не приводится.

### 9.5. Валидация метода

В набор валидации добавляются тесты (**Добавить тест**):

| Тест | Статус |
|---|---|
| Тест Граббса (один выброс) | verified — NIST e-Handbook §1.3.5.17.1 |
| Однофакторный ANOVA (s_r, s_b, s_I) | verified — NIST §7.4.3, §2.4.4 |
| Двухвыборочный t-тест | verified — NIST §1.3.5.3 |
| F-тест (две дисперсии) | verified — NIST §1.3.5.9 |
| t-тест извлечения (recovery) | verified — QUAM:2012 A4 |
| Линейность (регрессия) | OLS — verified (раздел 6) |
| Тест Кохрена C | unverified — ISO 5725-2 в репозитории нет |
| LOD / LOQ | unverified |

**Программа сама не удаляет значения.** Тест Граббса только указывает подозрительное значение. **Исключить** его из расчёта — решение пользователя: нужен комментарий не короче 10 символов, выполняет только администратор лаборатории, действие записывается в журнал аудита. Повторный тест Граббса автоматически не выполняется.

В блоке **Черновик шаблона top-down** по результатам ANOVA и извлечения создаётся личный шаблон top-down пользователя (`DRAFT`) — кнопка **Создать черновик**.

Пример. Источник: NIST/SEMATECH e-Handbook of Statistical Methods, §1.3.5.17.1 (тест Граббса). Проверка: `tests/engine/validation.test.js` (verified). Восемь значений: 199,31; 199,53; 200,19; 200,82; 201,92; 201,95; 202,18; 245,57. Верхний односторонний тест, α = 0,05. Результат в источнике: G = 2,4687, критическое значение 2,032 — наибольшее значение (245,57) отмечается как выброс. Примечание: источник привёл G, усечённое до четырёх знаков (значение программы 2,46876…).

## 10. Правило принятия решения и заключение о соответствии

Соответствие оценивается по JCGM 106:2012 §7–8 и ILAC G8:09/2019. Настройки на вкладке **Тип B**:

- **Пределы допускаемой погрешности MPE (±)** или явные пределы — **Нижний предел**, **Верхний предел** (односторонние или двусторонние);
- **Правило принятия решения**: **не выбрано**, **Простая приёмка (w = 0)**, **Защитная полоса w = r·U** (с полем **Множитель r**);
- **Вид заключения**: **Бинарное (соответствует / не соответствует)** или **Небинарное (с условными результатами)**;
- **Согласование с заказчиком (номер)**.

Программа вычисляет интервал приёмки, TUR = T / (2U) и вероятность соответствия p_c (в предположении нормального распределения).

**Основное правило: если не указаны правило принятия решения, предел или тип модели, заключение о соответствии не выдаётся.** Правило по умолчанию из настроек лаборатории или шаблона заранее подставляется в поле выбора, но записывается в расчёт только после подтверждения пользователем.

Замечания по TUR: TUR < 1 — предупреждение; 1 ≤ TUR < 4 — сведения (соотношение 4:1 — практика, источником не подтверждено).

## 11. Отчёт, импорт и экспорт

### 11.1. Формы отчёта

В списке **Форма отчёта** четыре формы: **Приложение к сертификату калибровки**, **Раздел протокола испытаний**, **Обоснование бюджета неопределённости (CMC)**, **Заключение о соответствии**.

В окне **Реквизиты** заполняются реквизиты лаборатории и документа. Незаполненные реквизиты указываются в отчёте. Перечень реквизитов опирается на ISO/IEC 17025 §7.8.2.1 — не проверено (раздел 1.2). Реквизиты на сервер не отправляются (раздел 1.4).

### 11.2. Нижняя часть отчёта

Внизу каждого отчёта выводятся: версия программы и расчётного ядра (`ENGINE_VERSION`), **Сборка (хеш расчётного ядра)**, шаблон (или «без шаблона»), **ID и дата расчёта**, **SHA-256 (канонический JSON, RFC 8785)** и QR-код (с ID расчёта и этим хешем). Хеш берётся от полного JSON-экспорта расчёта: при изменении входных данных или результата меняется и хеш.

### 11.3. Экспорт

На вкладках **Результаты**, **Регрессия**, **Top-down** и **Специальные режимы**:

- **Экспорт JSON** — документ расчёта в формате `uc-calc/1`: входные данные, настройки, результат и хеш;
- **Экспорт Excel (.xlsx)** и **Экспорт CSV** — результат, входные данные, бюджет, замечания. Числа не округлены; округлённый вид, как в отчёте, приводится отдельно.

### 11.4. Импорт

- **Импорт из файла (.xlsx, .csv)** — загружает наблюдения в таблицу. Выбираются лист, разделитель и сопоставление столбцов, есть предпросмотр. Ограничения: 5 МБ, 10 000 строк, 200 столбцов. Файл читается только в браузере; формулы не вычисляются — берутся только сохранённые в файле значения.
- **Открыть файл расчёта (JSON)** — проверяет файл `uc-calc/1`: сверяется хеш и расчёт выполняется заново.

### 11.5. Экспорт → импорт → повторный расчёт

При открытии JSON-файла программа заново выполняет расчёт по входным данным и сравнивает с сохранённым результатом:

- «Хеш проверен — файл не изменён» и «Пересчитано: результат воспроизведён в точности.» — файл цел и результат воспроизводится;
- «Хеш не совпал» — файл изменён или повреждён;
- «результат ОТЛИЧАЕТСЯ от сохранённого» или «Файл создан в другой версии движка.» — сравните версии ядра в файле и текущую.

После этого расчёт можно **Открыть в редакторе**. Эта проверка удобна и для собственной валидации лаборатории (раздел 12).

## 12. Валидация и версия

### 12.1. Страница «Валидация»

Страница «Валидация» на сайте (`validation.html`) показывает текущую версию расчётного ядра, идентификатор сборки и ссылку на отчёт о валидации. На странице: текущая версия (версия ядра, сборка, время сборки, хеш ядра, ваш браузер), документы (отчёт о валидации, план валидации, требования и матрица прослеживаемости, управление изменениями, известные ограничения, вопросы и ответы для эксперта, шаблоны PQ и URS, это руководство), известные ограничения (кратко) и история версий. Документы и история версий видны только на сайте, собранном через GitHub Actions; в копии без шага сборки страница об этом напоминает.

Собственная проверка программы состоит из примеров из нормативных документов (каждое ожидаемое значение — с пунктом источника), 9 эталонных точек из лабораторных файлов Excel и хеша файлов расчётного ядра. Таблица охвата — в [матрице валидации](../validation/RTM.md).

### 12.2. Баннер новой версии

Когда на сайте выходит новая версия, на странице показывается баннер. Страницу вы обновляете сами: чтобы введённые данные не потерялись, страница не обновляется автоматически. Перед обновлением сохраните текущий расчёт кнопкой **Экспорт JSON**. Текст баннера: «Вышла новая версия — обновите страницу…»; его можно закрыть кнопкой **Закрыть** (для этой версии он больше не появится).

При любом изменении, влияющем на результат расчёта, версия ядра повышается и изменение записывается в [журнал изменений](../../CHANGELOG.md).

### 12.3. Собственная проверка лаборатории (PQ)

Перед внедрением программы в рабочий процесс и после каждой новой версии ядра лаборатория должна провести проверку на своих примерах. Для этого используйте [шаблон протокола PQ](../validation/PQ_PROTOCOL_TEMPLATE.md). Рекомендуемый порядок:

1. Выберите хотя бы один пример по своей методике, рассчитанный независимо (например, в Excel).
2. Рассчитайте его в программе и сравните y, u_c, ν_eff, k, U.
3. Сохраните расчёт кнопкой **Экспорт JSON**; запишите в протокол версию ядра, сборку и хеш SHA-256.
4. После выхода новой версии откройте этот файл кнопкой **Открыть файл расчёта (JSON)** и убедитесь, что результат воспроизводится в точности.

## 13. Ограничения

Наиболее важные ограничения (полный перечень — [известные ограничения](../validation/KNOWN_LIMITATIONS.md)):

- **ISO/IEC 17025:2017** — текста в репозитории нет; ссылки на него и перечень реквизитов отчёта не проверены.
- **Режим BETA:** микробиология (ISO 19036) — не подтверждён примером из источника.
- **Методы unverified:** в регрессии — WLS, GLS, WTLS и полином; в top-down — части, опирающиеся на ISO 21748; логнормальное распределение; формулы и границы показателей PT (ISO 13528); тест Кохрена; LOD / LOQ; формула межкалибровочного интервала.
- **Неявная модель:** метода Монте-Карло нет; формы ввода на основном экране нет.
- **Наименьшая область охвата** — только для двух выходов.
- **Монте-Карло:** побитовая воспроизводимость — только в пределах одной версии JS-движка; при n_dig = 2 и δ/5 расчёт часто достигает предела M (с предупреждением).
- **Единицы входных величин:** отдельного поля в интерфейсе нет.
- **Шаблоны:** все поставляемые с программой шаблоны имеют статус `DRAFT` и не содержат чисел.
- **Раздел «Лаборатория»:** нет матричного / графического вида CMC, экспорта реестра в `.xlsx`, трендовых правил PT и правки раунда на месте.
- **Роли:** в локальном режиме ограничение по ролям действует на уровне предупреждения.
- **Не просмотрено вручную в браузере:** отдельные формы печатного отчёта, окно специальных режимов, разделы проверки квалификации и валидации (проверены только автоматическими тестами).
- **Данные только в браузере:** при очистке хранилища браузера неэкспортированные расчёты и реестр теряются.
- **Ответственность:** программа не заменяет решения метролога — за перечень источников, распределения и правило принятия решения отвечает лаборатория.

## 14. Интерфейс (2.0)

Интерфейс адаптируется к телефону, планшету и компьютеру. Методы расчёта и результаты прежние — изменился только внешний вид.

### 14.1. Оболочка и навигация

- **Верхняя панель:** путь (раздел / ID расчёта), поиск команд, язык (UZ / RU / EN), тема (тёмная / светлая), меню профиля, «Отчёт».
- **Поиск команд:** Ctrl+K — находит раздел, шаблон или действие по названию; выбор стрелками, Enter — открыть, Esc — закрыть.
- **Левое меню** (широкий экран): «Расчёт» (GUM, Монте-Карло, модель с несколькими выходами), «Методы» (регрессия, top-down, специальные режимы), «Лаборатория» (контрольные карты, реестр эталонов, проверки квалификации, валидация). На планшете — узкая колонка с иконками; на телефоне — нижняя навигация и кнопка основного действия.
- **Шаги:** Модель → Тип A → Тип B → Результат → Отчёт. Выполненный шаг отмечен зелёным знаком, текущий выделен.
- **Настройки сессии** (число измерений, параметры, пресеты) — под кнопкой «Сессия» на странице ввода.

### 14.2. Экран результатов

- **Основная карточка результата:** y ± U (округлённые), k, P, ν_eff и правило для него.
- **Лента неопределённости:** горизонтальная ось — отклонение от y (в единицах U); кривая — плотность N(y, u_c); жёлтая рамка — y ± U. Если выполнен расчёт Монте-Карло, ниже показаны его интервалы охвата (кратчайший и вероятностно-симметричный). Гистограмма не строится.
- **Плитки показателей:** u_c, ν_eff, k, U и доля доминирующего источника (выделяется, если больше 50 %).
- **Бюджет:** «Таблица» или «Парето» (источники по убыванию доли). В таблице есть столбец νᵢ; малое ν (меньше 10) выделено жёлтым.
- **Правая панель** (на узком экране — внизу): результаты проверки, параметры расчёта, сравнение с Монте-Карло.

### 14.3. Ввод источника типа B

Кнопка «Изменить» на карточке источника открывает лист: на телефоне — снизу, на широком экране — справа. Распределение выбирается из ряда кнопок, стандартная неопределённость показывается сразу при вводе значения. В качестве десятичного разделителя принимается и запятая. Кнопка «Выбрать из реестра» есть и внутри листа. Esc или «Готово» закрывает лист.

### 14.4. Вид отчёта и печать

Шаг «Отчёт» показывает документ на белом листе A4. Форма (одна из четырёх) переключается кнопками сверху. «Печать» — окно печати браузера; «PDF» — в этом окне выбирается «Сохранить как PDF». При печати заголовок таблицы повторяется на каждой странице, нижний колонтитул (версия движка, сборка, хеш, QR) выводится на каждой странице.

### 14.5. Визуальная лаборатория

Прямая ссылка: к адресу страницы добавляется `#lab`. Учебный инструмент: живой вид Монте-Карло, симулятор соответствия, предельные случаи, дрейф контрольной карты, корреляция и чувствительность бюджета. Числа берутся из расчётного движка. В каждом режиме стоит метка «учебный пример»; результаты отсюда не сохраняются и не попадают в отчёт.

### 14.6. Доступность

Все действия выполняются с клавиатуры, фокус виден. Высота нажимаемых элементов не меньше 44 px. Если в системе включено «уменьшение движения», анимация отключается. Выбор темы сохраняется в браузере.
